## Для разработки

- `lib/domain/image_to_grid/`: конвейер «картинка → схема» из независимых шагов, каждый — чистая функция со своими тестами. `CellSampler` (ресэмплинг: средний цвет по площади под ячейкой с учётом `GridGeometry` и `CellMetrics`, прозрачные ячейки пустые, вес важности ячейки из маски), `GridSizing.rowsForColumns` (число рядов под пропорции картинки), `LabQuantizer` (median cut → k-means в Lab, веса важности, детерминизм по `seed`), `PaletteConstraint` (свободно / каталог по материалу, бренду, серии, размеру / заданный список; снап к допустимым цветам по ΔE2000), `ColorAssigner` (ближайший цвет по ΔE2000, дизеринг Флойда–Стейнберга), `ImageToGridPipeline` соединяет шаги.
- Вход: `ImageToGridRequest` с `SourceImage` (RGBA `Uint8List`) и необязательной маской важности (`Float32List`, по умолчанию все 1). Выход: `GeneratedPattern` (`Grid` + `PaletteEntry`: цвет и позиция каталога или `null`); палитра упорядочена по частоте, неиспользуемых цветов нет.
- Точка расширения для T47–T49: `PatternStep` (`apply(pattern, context)`) в `ImageToGridRequest.steps` выполняется после привязки к палитре и получает геометрию и веса ячеек.
- Запуск в изоляте: интерфейс `ImageToGridRunner` в домене, `IsolateImageToGridRunner` (`Isolate.run`) в data, регистрация в `di.dart`.
- Миграций БД, новых зависимостей и разрешений нет.
