## Для разработки

- Домен проектов (`lib/domain/projects`): `Project` (id, name, status `idea/inProgress/done`, craft `beading/crossStitch`, technique, contentKind `image/grid/steps`, notes, coverPath, lastWorkedAt), `Technique` привязана к `Craft` (бисер: loom, peyote, brick, square, offLoom; вышивка: crossStitch, tent). Техника не из своего ремесла → `ValidationFailure`.
- `ProjectRepository` (поток живых проектов по `lastWorkedAt`, мягкое удаление) и `DriftProjectRepository`; таблица `projects` со служебными колонками синхронизации.
- **Миграция БД v1 → v2** (`schemaVersion` = 2): создаётся таблица `projects`. Дамп `drift_schema_v2.json`, тесты миграции перегенерированы `drift_dev make-migrations`.
- Use cases: `CreateProject`, `RenameProject`, `DuplicateProject`, `DeleteProject`, `ChangeProjectStatus`, `WatchProjects(filter)`, `UpdateNotes`, `TouchProject`. Все зарегистрированы в DI как фабрики.
- `DuplicateProject` принимает список `ProjectContentCloner` (`supports(kind)` + `clone`); T06 и T14 добавляют свои и перерегистрируют фабрику в DI. Сбой клонера удаляет копию. Копия: статус «идея», без обложки, заметки сохраняются.
- `AppEvents` (`lib/domain/events`): шина с событием `ProjectCompleted`, публикуется при переходе проекта в «готово» (повтор «готово» события не даёт). Задачи пасхалок добавят остальные события.
- Поиск `ProjectFilter` по названию — без регистра и без различия «ё/е», в Dart (SQLite `lower()` не знает кириллицу).
- Тест `migration_test.dart` заменён сгенерированным `app_database/migration_test.dart` плюс тест сохранения данных при v1 → v2.
