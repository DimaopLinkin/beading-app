## Для разработки

- Серверная часть синхронизации (ADR-0006): `supabase/migrations/20261112000000_sync_records.sql`: таблица `sync_records` с правилами доступа «каждый видит только свои строки», триггер LWW с блокировкой по пользователю (курсор `server_seq` без пропусков), realtime-публикация, закрытый бакет `blobs`, функция `keep_alive()`.
- Клиент: `SupabaseSyncRemote` (pull по курсору порциями, push через upsert, сервер сам отвергает устаревшие), `BlobExternalizer` (сетка, слои и файлы страниц книг уходят в Storage сжатыми, под именем по хешу; повторно не загружаются; при приёме проверяется хеш, не скачался файл — запись не применяется), тонкие обёртки `RecordTransport`/`BlobTransport` над `supabase_flutter`. Тесты на фейковых серверах.
- `.github/workflows/supabase-keepalive.yml`: ежедневный пинг от паузы бесплатного проекта; нужны секреты репозитория `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`, без них шаг только предупреждает.
- Ограничение: удаление файлов Storage после надгробий и очистка сирот пока не сделаны (отдельная задача).
- Зависимости: `supabase_flutter`, `flutter_secure_storage`, `crypto`.
