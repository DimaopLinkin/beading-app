# ADR 0001: Бисер и вышивка крестиком в одной доменной модели

- **Статус:** принято
- **Дата:** 2026-11-09
- **Задача:** A04 ([cross-stitch.md](../cross-stitch.md))

## Контекст

Настя, кроме бисероплетения, много вышивает крестиком. Дмитрий спросил, можно ли добавить в приложение те же возможности для вышивки: схемы из книг и PDF, свои схемы, генерацию из фото, прогресс. План [tasks.md](../tasks.md) пока описывает только бисер, а задачи доменного ядра (T03, T04, T11, T12) стартуют сейчас. Если они зашьют «бусину» в сущности, вышивку потом придётся встраивать миграциями и переписыванием тестов.

Счётная вышивка — прямоугольная сетка цветов, как станочное плетение, но с квадратной ячейкой канвы, каталогами мулине (DMC, Anchor, Madeira, «Гамма»), смешанными нитями, частичными крестиками, бэкстичем и узелками, прогрессом по отдельным клеткам и своими форматами файлов (`.oxs`, `.xsd`). Подробности — в [cross-stitch.md](../cross-stitch.md), разделы 2 и 4.

## Решение

1. **Ремесло — поле проекта.** `Project.craft: Craft` (`beading`, `crossStitch`), по умолчанию `beading`. Техника валидируется по ремеслу. Одна библиотека, одна база, один формат `.biser`, одна синхронизация.
2. **Схема вышивки — `GridPattern` с геометрией `rectangular`.** Отдельного вида контента нет. Редактор, отрисовка, генератор, кодек и синхронизация переиспользуются.
3. **`CellMetrics` — общий интерфейс размера ячейки.** `GridGeometry` зависит от `CellMetrics` (ширина и высота ячейки в мм), а не от `BeadSize`. `BeadSize` (диаметр, длина вдоль отверстия, вес) и `Fabric` (вид канвы, плотность, «через N», цвет) — две реализации. Для бусины ориентацию (что ширина, что высота) выбирает геометрия по технике.
4. **Один каталог для бисера и ниток.** `CatalogColor(material: bead | floss, brand, series, code, name, rgb, attributes)`, таблица `catalog_colors`. Поиск, фильтр по бренду и подбор по ΔE2000 общие.
5. **`PatternColor` ссылается на 1–2 позиции каталога** (`components`), хранит `finish`. Число сложений — `StitchSpec` схемы с переопределением у цвета. Снимок палитры остаётся снимком.
6. **Элементы вышивки сверх полного крестика — разреженные слои** (`StitchLayers`): частичные крестики в клетках, линии (бэкстич, прямые стежки) на полушаговой решётке узлов, точки (узелки, бисер). Сериализуются отдельным версионированным `StitchLayersCodec`, `GridCodec` v1 не меняется. У бисерных схем слои пусты.
7. **Прогресс по клеткам — битовые блоки 16×16** (`grid_progress_cells`) за интерфейсом `GridProgressStore`. Слияние при синхронизации — побитовое ИЛИ плюс битовая карта снятий с временем; прогресс по рядам для бисера не меняется.
8. **Поведение, зависящее от ремесла, — стратегии за интерфейсами:** `MaterialEstimator` (`BeadEstimate`, `FlossEstimate`), порядок работы (`ReadingOrder` и word chart для бисера, `StitchGuide` для вышивки), пункты `NewProjectEntry` с полем `craft`.
9. **Генератор из фото общий** и устроен как конвейер шагов с маской важности на входе. Маски на устройстве — Apple Vision за доменным интерфейсом `ImageMasks`. Облачный ИИ не входит в основной генератор (только как опциональный помощник после исследования A06).
10. **Форматы вышивки — кодеки в `data`:** `OxsCodec` (обязательно), `XsdDecoder` по MIT-спецификации `xsp-specs` (желательно). Код под GPL не используем.

## Рассмотренные альтернативы

| Вариант | Почему нет |
|---|---|
| Отдельное приложение для вышивки | Дублирование всего: библиотеки, БД, синхронизации, пасхалок; Насте два приложения вместо одного |
| Отдельный вид контента `StitchPattern` | Пришлось бы дублировать редактор, отрисовку, генератор и кодек ради отличий, которые укладываются в слои и стратегии |
| Хранить частичные крестики и бэкстич внутри `Grid` (больше бит на клетку) | Бэкстич лежит на рёбрах и узлах, а не в клетках; раздувает каждую бисерную схему; ломает `GridCodec` v1 |
| Прогресс вышивки строкой на клетку, как ряды бисера | 60 000–120 000 строк на схему; медленно и тяжело для синхронизации |
| Прогресс одним BLOB на схему с LWW | Отметки, сделанные на двух устройствах, теряются при слиянии |
| Генерировать схему облачной моделью «картинка → схема» | Модели не выдают точную сетку с номерами ниток; цена, сеть и приватность фото |

## Последствия

- Задачи T03, T04, T11, T12 получают небольшие обобщения до старта (поля `craft`, `CellMetrics`, `components`, `finish`, ключи настроек по ремеслу). T05, T06, T13, T14, T15, T18, T21, T24 — уточнения, внесённые в их разделы.
- Новая веха M5 «Вышивка» (T36–T46, T49) только добавляет код и таблицы, не переписывая M1–M3.
- Две задачи генератора (T47, T48) в M3 улучшают генерацию и для бисера.
- Схема БД растёт: `projects.craft`, `catalog_colors.material`, `grid_patterns.cell_metrics/layers`, `grid_progress_cells`, `image_pattern_pages`. Каждое изменение — со своей миграцией и тестом, как обычно.
