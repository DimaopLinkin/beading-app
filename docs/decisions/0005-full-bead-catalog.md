# ADR-0005. Полный каталог бисера: данные из пакета beadloo-assets (MIT) с перерасчётом RGB по фото

- **Статус:** принято
- **Дата:** 2026-11-10
- **Задача:** T59

## Контекст

Стартовый каталог T13 содержал 42 цвета Delica и 34 цвета Toho, а RGB подбирался по названию. Галерея T51 показала последствия: с каталогом у фото кошки остаётся 5 цветов и ΔE 9,6, без каталога 3,7. Для красивой схемы нужен полный каталог с измеренными цветами. Проверка стартового набора по фото выявила и другое: часть пар «артикул — название», скопированных с розничных страниц, не соответствует настоящей бусине.

Источник должен быть публичным, с понятной лицензией, содержать артикулы и измеримый цвет. Производители не публикуют таблиц RGB.

## Рассмотренные варианты

1. **Скрапинг сайтов Miyuki и Toho самим.** Свой код, свои фото; сайт Miyuki банит клиента, который часто получает 404. Юридически серо: копируем чужие фото и тексты. Отклонено.
2. **Розничные магазины.** Так был сделан T13: артикулы и названия расходятся между магазинами, цвета неточные. Отклонено.
3. **`liu-dow/beads` (curated, 76 цветов Delica) и `Ennoriel/bead-pattern`.** Маленький набор с цветами «по вкусу» автора, у второго нет явной привязки к названиям. Отклонено.
4. **`adamaszczos/beadloo-assets` (MIT).** Содержит 1 398 Delica 11/0, 929 Toho 11/0, а также Delica 10/0, 15/0, 8/0, Toho 15/0, 8/0 и др., рокайль Miyuki и Preciosa. Артикулы и признаки собраны из официальных данных с реестром происхождения каждой позиции (`sources/miyuki/registry`), есть 48×48-фото бусин. RGB как таковых в репозитории нет (они генерируются в неопубликованную папку), названий тоже. **Выбрано.**

## Решение

- Берём из пакета артикул, группу цвета, тип стекла, отделку, статус «снят с производства» (MIT; копирайт Adam Nowakowski, лицензия не требует ничего, кроме сохранения уведомления: ссылка и коммит — в README каталога и в поле `source` файлов).
- RGB считаем сами скриптом `tool/build_full_catalog.py` по 48×48-фото: в мире пакета это тот же приём, который даёт его «colorMappings». Хранится в каталоге только число-цвет, не картинка. Сверка вручную на нескольких позициях (Toho 612 и 47, Delica 2523 и 2525) показала, что измеренный цвет совпадает с фото, а старые «по названию» были неверны.
- Названия: у Toho из группы цвета, у Delica из признаков. Торговое название не придумываем.
- `finish` сводится к одному значению из прежнего белого списка по приоритету. Новых значений не вводим, чтобы не трогать отрисовку (`BeadFinish.parse`).
- Версия файлов 2; миграция БД не нужна: `CatalogSeeder` перечитывает файл при смене `version`.
- Скрипт воспроизводим: `python3 tool/build_full_catalog.py <клон пакета> <коммит>`.

## Последствия

- Каталог растёт с 76 до 2 327 цветов; первое наполнение базы при запуске занимает заметно дольше (одна транзакция на файл). Если замер на устройстве покажет заметную задержку, наполнение переносится в фон — отдельной задачей.
- Точность RGB ограничена фото производителя и приёмом усреднения (см. README каталога). Для подбора «ближайшего по ΔE» этого достаточно, для цветопробы печати нет.
- У 59 Delica в источнике вместо фото россыпи только образец со страницы каталога; их RGB грубее. Не отмечаем отдельно: признака в данных пакета для файлов нет.
- Галерея T51 с новым каталогом (вариант `t24-catalog`): ΔE снижается примерно вдвое (кошка 9,6 → 3,9; кофе 7,9 → 4,6; портрет 8,0 → 6,2; рукописный текст 5,2 → 1,4), цветов у кошки 10 вместо 5. Одиночных клеток становится больше (кошка, станок: 24 → 103), потому что у конвейера T24 теперь есть близкие друг к другу цвета, а очистки нет; их убирают T52 и T53. `test/fixtures/photos/baseline.json` обновлён сознательно, как описано в README галереи.
- Остальные размеры (T50) добавляются тем же скриптом (новая запись в `build`) без новых решений.
