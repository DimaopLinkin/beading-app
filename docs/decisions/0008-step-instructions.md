# ADR-0008. Пошаговые инструкции для маршрутных техник бисера

- **Статус:** принято
- **Дата:** 2026-11-15
- **Задача:** T33 (NICE-3), разбиение T33a–T33e в [tasks.md](../tasks.md#t33--пошаговые-инструкции-для-маршрутных-техник)

## Контекст

RAW/CRAW, ёлочка, сетка (netting), жгуты, спирали и цветы не описываются сеткой ([research.md](../research.md), таблица техник): нужна инструкция «шаг = текст + картинки», часто с повторами («повторите шаги 3–6 ещё 10 раз», «до нужной длины»). Заготовка уже есть: `ContentKind.steps`, `Technique.offLoom`, заглушки в `router.dart`, `LoadProjectPreview`, `ExportProjects`. Только бисер; генератор из фото и код вышивки не трогаем. Схема drift сейчас v16, `.biser` v4, синхронизация по ADR-0006 (строка на запись, LWW).

## Решение

### Доменная модель (`lib/domain/steps/`)

```text
StepPattern  id, projectId, palette: List<PatternColor>, sections: List<StepSection>, templateId?
StepSection  id, title, repeat: Repeat, steps: List<InstructionStep>
InstructionStep  id, text, imageIds: List<String>, beads: List<StepBead>, repeat: Repeat
StepBead     colorIndex (в palette), count            → показывается как word chart «3 × A»
Repeat       times(n ≥ 1) | untilDone                 → «повторить N раз» / «до нужной длины»
StepImage    id, path, width, height                  → файл через FileStore
```

- Палитра — **снимок** `PatternColor`, как у `GridPattern` (выбор из каталога T13 переиспользуется, правка каталога не меняет инструкцию). Материалы проекта (T20) считаются сложением `beads × повторы`; у `untilDone` — «на один повтор».
- Секции обязательны, но одна безымянная секция в UI не показывается (простая инструкция = плоский список).
- Повтор есть и у шага, и у секции; вложенность только на два уровня (секция → шаг). Глубже не нужно для известных техник, и UI становится нечитаемым.
- `id` шагов и секций стабильны (UUID v7): прогресс ссылается на `id`, поэтому перестановка и правка текста не сбивают «где я».
- Название `InstructionStep`, а не `PatternStep`: `PatternStep` уже занят генератором (`domain/image_to_grid`).

**Создание** (`CreateStepPattern`, проект `contentKind=steps`, `craft=beading`, техника по умолчанию `offLoom`, можно выбрать любую бисерную):
1. **Пустая** — одна секция, один пустой шаг.
2. **Из встроенного шаблона** — копия шаблона (не ссылка: шаблоны обновятся с приложением, а её проект — нет). Шаблоны лежат в `assets/step_templates/*.json` (ru), читаются через интерфейс `StepTemplateSource`; картинки шаблона копируются в хранилище проекта, чтобы проект был самодостаточным для экспорта и синхронизации. `templateId` сохраняется только для статистики и «начать заново».
3. **Из фото** — выбрать N фото (мастер-класс, скриншоты, страницы журнала) → N шагов, по фото на шаг, текст пустой. Это не генератор и не OCR.

«Мои шаблоны» отдельной сущностью не делаем: своя инструкция копируется через `DuplicateProject` (нужен `StepPatternContentCloner`). Отдельная библиотека — если попросит после A01.

### Хранение (drift, схема v17, одна миграция)

| Таблица | Поля сверх служебных | Почему так |
|---|---|---|
| `step_patterns` | project_id (unique, с учётом надгробий), body TEXT (JSON), body_version, template_id NULL | Вся структура — **один документ**, кодек `StepPatternCodec` (v1) с тестами, как `GridCodec`. Инструкция маленькая (сотни шагов — десятки КБ), правит её один человек; документ даёт атомарную правку и тривиальный порядок шагов (порядок в массиве, без `position` и перенумерации строк). |
| `step_images` | pattern_id FK, path, width, height | Файл — отдельная запись, потому что ADR-0006 кладёт файлы в Storage по полю записи. Путь `step_patterns/{patternId}/{imageId}.png`, сжатие через `ImageProcessor` как у страниц книг (длинная сторона ≤ 2048). |
| `step_progress` | id = id `step_patterns`, section_id, section_pass, step_id, step_pass, finished | Курсор прогресса, одна запись (см. ниже). |

- `SaveStepPattern` в одной транзакции пишет документ и удаляет записи и файлы картинок, на которые документ больше не ссылается. Ссылка документа на отсутствующую картинку при чтении не ошибка (заглушка в UI): так переживается рассинхрон при слиянии.
- Нормализованные таблицы секций и шагов отклонены: перестановка меняла бы `position` у многих строк, LWW по строкам мог бы собрать порядок из двух устройств, натуральные ключи по позиции конфликтуют.

### Прогресс

- `StepsProgress` — **курсор**, а не множество отметок: `(sectionId, sectionPass, stepId, stepPass, finished)`. Отмечено всё, что раньше курсора в развёрнутой последовательности. Маршрутные техники плетутся строго по порядку; множество отметок на «повторить 200 раз» дало бы сотни строк и разъезжающиеся при слиянии отметки.
- Чистые функции в домене: `next` (повтор шага → следующий шаг → следующий проход секции → следующая секция → `finished`), `previous`, `jumpTo(stepId)` (касание по шагу), `fraction` (доля пройденных единиц; шаг `untilDone` считается одной единицей). Курсор на удалённый шаг сдвигается к ближайшему следующему существующему.
- Счётчик «повтор N из M» — это `stepPass`/`sectionPass`; для `untilDone` показывается «N-й повтор» без M и кнопка «дальше».
- Время — существующий `WorkSessionTracker` по проекту, как в T19: сессии не знают вида содержимого, поэтому T32 получает время steps-проектов без изменений. Для доли готовности T33 даёт реализацию того интерфейса прогресса, который заведёт T32 (или T32 вызывает `StepsProgressStore` + `fraction`). Последний шаг предлагает статус «готово» (`ProjectCompleted` для пасхалок), старт — `inProgress`.

### Синхронизация (ADR-0006) и `.biser`

| Сущность | `sync_id` | Нагрузка |
|---|---|---|
| `step_patterns` | `project_id` | `body` inline в `data` (текст), `data.v = 1`; родитель — `projects` |
| `step_images` | `{project_id}:{image_id}` | файл в Storage (правило «по полю», как страницы книг); родитель — `step_patterns` |
| `step_progress` | `project_id` | курсор, LWW отдельно от документа (как `grid_cursor`): «дальше» не переотправляет документ |

SQLite-триггеры outbox добавляются в `sync_triggers.dart` вместе с мапперами (T33b; отдельной миграцией v18, если T33a уже влит, и полной выгрузкой существующих steps-записей в outbox), иначе outbox получит сущность без маппера; ранги применения — после `projects`. Слияние — обычный LWW записи; правка документа на двух офлайн-устройствах теряет правки проигравшего целиком (принято: редактирует один человек). Новая версия кодека документа — новая `data.v`.

`.biser` v5: в `BiserProject` поле `steps` (документ как есть + `body_version`, картинки в `steps/{id}.png`, курсор). Читатель v5 принимает v1–v4; старое приложение на v5 уже отвечает «обновите приложение». Импорт «как новый» перевыдаёт `id` проекта, документа и картинок, `id` шагов внутри документа остаются (уникальны в документе).

### Слои и модули

- `domain/steps/`: сущности, `StepPatternRepository`, `StepsProgressStore`, `StepTemplateSource`, use cases (`CreateStepPattern`, `SaveStepPattern`, `StepNavigation` (next, previous, skipRepeat, jumpTo, reconcile)), `StepPatternContentCleaner/Cloner`, превью (картинка текущего шага или первая картинка).
- `domain/steps/`: `StepPatternCodec`; `data/steps/`: `DriftStepPatternRepository`, `AssetStepTemplateSource`; `data/db/tables/step_pattern_tables.dart`, DAO; мапперы в `data/sync/sync_entity_mappers.dart`.
- `presentation/steps/`: `template_library/`, `work/` (`StepsWorkCubit`), `editor/` (`StepsEditorCubit`).
- `app/composition/steps_module.dart` (`StepsModule`): репозиторий, cleaner и cloner в списки `AppDependencies`, маршруты, пункт `NewProjectEntry` «Пошаговая инструкция» (`craft=beading`); `router.dart` открывает `ContentKind.steps` → `AppRoutes.steps(id)`; `LoadProjectPreview` получает провайдер превью steps.

### Сценарии для Claude Design (промпт ведёт дизайнер в design-prompts.md)

1. **Библиотека шаблонов** (после «Новый проект → Пошаговая инструкция»): «Пустая», «Из фото», затем карточки встроенных техник (название, картинка, сложность, число шагов); просмотр шаблона перед созданием.
2. **Инструкция в работе:** крупный текст текущего шага (масштаб текста настраивается), фото на всю ширину с зумом, бусины шага чипами палитры «3 × A», большая кнопка «Готово / дальше», счётчик «повтор 4 из 10» и «секция 2 из 3», свайп назад, список шагов с галочками до курсора (касание — перейти), экран не гаснет, обе темы, Mac — список шагов сбоку.
3. **Редактор шагов:** список секций и шагов с перетаскиванием, шаг — текст, фото (камера/галерея, порядок, удалить), бусины из палитры, повтор (N раз / до нужной длины); палитра как в редакторе сеток; автосохранение.

## Последствия

- Новая миграция v17 с тестом со всех прошлых версий, `.biser` v5, три синхронизируемые сущности (`SyncSchema` растёт, отпечаток меняется — полный pull один раз).
- Содержание встроенных шаблонов (тексты, картинки, проверка правильности маршрута нити) — работа не инженерная, её подтверждают Настя и Дмитрий (T33e).
- Отметки шагов не по порядку не поддерживаются; если Настя попросит, курсор дополняется множеством отметок без смены остальной модели.


**Версии (T33b-R1-05, A-03).** Новая версия кодека документа ⇒ новая `data.v` записи синхронизации и новая версия формата `.biser`. Читатель `.biser`, не знающий версию документа, пока отвечает «файл повреждён»; это принято до появления v2 кодека. Путь картинки в записи — единственный источник истины: на втором устройстве файлы лежат под id инструкции отправителя.
