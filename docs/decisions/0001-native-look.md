# ADR-0001. Нативный вид на iOS и macOS

- **Статус:** принято (2026-11-09), по просьбе Дмитрия: приложение должно выглядеть максимально нативно, по возможности в Liquid Glass; Android и Windows не запускаем.
- **Контекст:** Flutter рисует интерфейс сам, поэтому «нативность» нужно строить намеренно. Целевые платформы — только iOS (iPhone 13 Pro Max) и macOS 26.x; пользователь — одна мастерица, которой важна привычность и удобство одной рукой.

## Решение

### 1. Только Apple-платформы
- В репозитории только папки `ios/` и `macos/`. Android, Windows, Web, Linux не создаём и не поддерживаем; ветвления «если Android» в коде нет.
- Это снимает потребность в адаптивных виджетах: везде используем Apple-вид.

### 2. Cupertino-first, а не Material 3
- Корень приложения — `CupertinoApp.router`, тема — `CupertinoThemeData` с `CupertinoDynamicColor` (пары светлый/тёмный, системная яркость по умолчанию, ручной выбор перекрывает яркость).
- Виджеты: `CupertinoNavigationBar`/`CupertinoSliverNavigationBar`, `CupertinoTabBar`, `CupertinoActionSheet`, `CupertinoAlertDialog`, `CupertinoSwitch`, `CupertinoSegmentedControl`/`CupertinoSlidingSegmentedControl`, `CupertinoContextMenu`, `CupertinoPageRoute` (свайп назад).
- Material допускается только как «скрытая зависимость» там, где у Cupertino нет аналога и виджету нужен Material-предок (например, некоторые поля ввода, `SelectionArea`, `InkWell`-эффекты). Весь такой код — в одном файле `lib/presentation/theme/material_bridge.dart`; прямой импорт `package:flutter/material.dart` в `lib/presentation` и `lib/app` запрещён проверкой в `scripts/check_architecture.sh` (исключение — этот файл).
- Шрифт — системный (SF Pro/SF Compact), без своих шрифтов; размеры подчиняются Dynamic Type (`MediaQuery.textScaler`). Цифры счётчика — табличные (`FontFeature.tabularFigures()`).
- Тактильный отклик — `HapticFeedback` в местах, где это делает нативное приложение (смена ряда, завершение).
- Токены: так как `ThemeExtension` работает только с Material `ThemeData`, наши токены (подсветка ряда, притушение, параметры стекла, отступы, радиусы) отдаются через `InheritedWidget` `AppTokens` (`context.tokens`). Цвета бусин — данные, не токены.

### 3. Liquid Glass
- Применяем там, где его даёт ОС: iOS 26+ и macOS 26+ (iPhone 13 Pro Max поддерживает iOS 26; её Mac — 26.x). Для более старых ОС — запасной вариант (полупрозрачная заливка + размытие фона).
- Flutter сам нативное стекло не рисует. Все стеклянные элементы живут за нашими виджетами `GlassBar`, `GlassPanel`, `GlassButton`, `GlassSheet` в `presentation/widgets/glass/`; экраны напрямую SwiftUI/пакеты не вызывают.
- Варианты реализации, которые сравнивает спайк **T01g** (итог — ADR-0002):
  1. **Нативные platform view со SwiftUI** (`glassEffect`, `GlassEffectContainer`) для панелей и тулбаров: максимальная нативность, но стоимость platform view (жесты, композиция над `CustomPainter`-схемой, отдельная работа на macOS через `AppKitView`).
  2. **Готовые пакеты** (шейдерные приближения Liquid Glass и обёртки нативных виджетов): их актуальность и поддержка macOS 26 нужно проверить на момент спайка, на память решения не принимаем.
  3. **Своё приближение** на `BackdropFilter` и фрагментном шейдере: полный контроль и работает в тестах, но это «похоже», а не нативное.
- Предварительная гипотеза, которую спайк подтверждает или опровергает: нативное стекло для навигационного слоя (бары, лист, плавающая панель), приближение — для мелких плавающих кнопок над схемой.
- Правила применения — в [cross-cutting.md](../cross-cutting.md#liquid-glass): стекло только на слое управления, контент непрозрачный, нет «стекла на стекле», читаемость поверх ярких бусин.

### 4. Внешний вид на macOS
- Окно: нативное оформление — скрытая полоса заголовка с контентом на всё окно (через `window_manager`, либо нативные вызовы `NSWindow`, если пакета не хватит), системные кнопки светофора, тулбар-стекло.
- Строка меню — нативная через `PlatformMenuBar` (Файл, Правка: Отменить/Повторить, Вид), горячие клавиши (`⌘Z`, `⇧⌘Z`, `⌘N`, `⌘,`), контекстные меню правой кнопкой, наведение курсора (hover), прокрутка трекпадом.
- Раскладка: при ширине ≥ 700 pt — боковая панель (sidebar, стекло) + контент, иначе экран как на iPhone.
- Пакет `macos_ui` по умолчанию **не берём**: он рисует собственный macOS-вид, и его соответствие macOS 26 (Liquid Glass) нужно проверять; Cupertino + наш слой стекла + нативное меню и окно дают более предсказуемый результат. Спайк T01g может пересмотреть, если пакет окажется актуальным.

### 5. Иконки: SF Symbols
- Все иконки — через абстракцию `AppIcons`. По умолчанию `CupertinoIcons` (это не SF Symbols, а похожий набор, части нужных нам символов в нём нет).
- Настоящие SF Symbols используем там, где доступны нативно (стеклянные бары через нативный слой, если спайк выберет его), и для остальных мест — собственные векторные иконки, нарисованные под вес и стиль SF (кисть, заливка, пипетка, зеркало, линейка). Лицензия SF Symbols разрешает использование только в приложениях для платформ Apple — наш случай.
- Иконки хранятся в `assets/icons/` (SVG) и подключаются через `AppIcons`; заменить реализацию можно без правки экранов.

## Последствия

**Для T01 (тема и токены):** строить на `CupertinoThemeData` + `AppTokens`, а не на `ThemeData`/`ThemeExtension`; перевести `lib/app/app.dart` с `MaterialApp.router` на `CupertinoApp.router` и `library_screen.dart` на Cupertino-виджеты; добавить `AppIcons` и `material_bridge.dart`; добавить в `scripts/check_architecture.sh` запрет прямого `package:flutter/material.dart` (с исключением для `material_bridge.dart`) и тест этого правила.
**Для T01g:** спайк Liquid Glass, результат — ADR-0002 и виджеты `presentation/widgets/glass/`.
**Для T01b:** UI kit из Claude Design переносится в токены `AppTokens`, а не в Material `ColorScheme`.
**Для задач экранов (T05, T07, T09, T15, T17, T19, T20, T23, T25):** только Cupertino-виджеты и стеклянные виджеты из T01g; навигация — `CupertinoPage`; на macOS — sidebar и горячие клавиши в рамках задачи. Это пункт чек-листа ревью (`ui`).
**Для T02 (оболочка):** к размеру окна добавляются нативное оформление окна и строка меню `PlatformMenuBar`.
**Риски:** стеклянные панели над тяжёлой `CustomPainter`-схемой могут стоить кадров (проверяет T01g, цель 60 fps на 100×400); нативные platform view усложняют жесты; пакеты могут отставать от новых версий iOS/macOS. Запасной вариант без нативного стекла всегда есть.
