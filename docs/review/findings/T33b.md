## Проверено, замечаний нет

- Миграция v16 → v17 → v18: данные не теряются, триггеры `statementsBeforeSteps` не ссылаются на несуществующие таблицы, v15→v16 и v13→v14 строятся от урезанных списков; выгрузка существующих `step_*` в очередь покрыта тестом.
- Ключи слияния `project_id`, `project_id:image_id`, `project_id` согласованы между триггерами, `allSyncIds` и `read`; локальный `id` инструкции у устройств разный, и маппер корректно ищет по `project_id` (включая надгробие).
- Импорт «как новый»: ссылки шагов на картинки переписываются, id шагов сохраняются, курсор остаётся валидным; конфликты id учитываются через `_occupiedIds`.
- Файл v5 с версией выше 5 отклоняется общей проверкой; файлы v1–v4 читаются (поле `steps` необязательное), версия файла без инструкций остаётся прежней.

### Проверено (архитектура), замечаний нет

- Направление зависимостей: `domain/sharing/biser` зависит только от `domain/steps`; мапперы и триггеры лежат в `data/` по ADR-0008; `SharingModule` получает `StepsModule` через конструктор, граф модулей ацикличен (ADR-0007).
- Ключи слияния, ранги (документ 1, картинка и курсор 2) и `parentKey` согласованы с таблицей ADR-0006 и с триггерами. «Дальше» отправляет только `step_progress`, документ не переотправляется. Картинка — файловая сущность в `BlobExternalizer.fileEntities`, правило «по полю» соблюдено.
- Миграция для 0.3.0: v16 → v17 (только таблицы) → v18 (триггеры и постановка существующих строк в очередь). У пользователей 0.3.0 строк `step_*` нет, данные вышивки и запасов не трогаются; отпечаток схемы меняется, поэтому после обновления будет один полный pull (ожидаемо по ADR-0008).
- `.biser` v5: поле `steps` необязательное, версия файла выбирается по содержимому (без инструкций файл остаётся v1–v4 и читается старым приложением), читатель принимает v1–v4, v6+ отклоняется.
