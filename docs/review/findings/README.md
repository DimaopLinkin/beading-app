# Журнал замечаний ревью

Один файл на задачу: `T05.md`. Ревьюер дописывает, исполнитель отвечает в колонке «Статус». Файл коммитится в ветку задачи и попадает в `dev` вместе с ней — так следующий ревьюер видит историю и ищет повторы.

Шаблон:

```markdown
# T05 — Импорт изображения

| ID | Раунд | Кто | Серьёзность | Категория | Где | Суть | Повтор | Статус |
|---|---|---|---|---|---|---|---|---|
| T05-R1-01 | 1 | code | major | test | lib/domain/generator/quantizer.dart:42 | Нет теста на изображение из одного цвета | — | fixed 1a2b3c |
| T05-R1-02 | 1 | code | minor | arch | lib/presentation/generator/generator_cubit.dart:10 | Импорт из data | recurrence of T03-R2-01 | fixed 4d5e6f |
| T05-R2-01 | 2 | design | nit | style | ... | ... | — | rejected: ... (принято) |
```

«Кто»: `code`, `arch`, `design`, `research`, `fact` (см. [team.md](../../team.md)). Строки дописывает тред задачи скриптом `scripts/team/record_review.sh`, дословно из ответа ревьюера.

Статусы: `open`, `fixed <commit>`, `rejected?: <причина>` (исполнитель предлагает отклонить), `rejected: <причина> (принято)` (ревьюер согласился), `reopened`. Закрыты только `fixed` и `rejected … (принято)`; остальные блокируют мёрж (`scripts/team/merge_gate.sh`). Статус существующей строки меняет тред задачи: `fixed`/`rejected?` — по своему исправлению, `rejected … (принято)`/`reopened` — дословно по решению ревьюера.
