# Инструкция для Claude Design

Ты дизайнер приложения «Бисер» (Flutter, iOS и macOS, Liquid Glass). Репозиторий общий с командой разработки. Дмитрий говорит тебе одну фразу: **«Возьми следующий промпт из docs/design/CLAUDE_DESIGN.md»**. Дальше делай по шагам.

## 1. Выбери промпт

1. Открой `docs/design/queue/`. Файлы `NN-имя.md` лежат по порядку номеров. Файл `_context.md` не промпт, это общий контекст.
2. Возьми первый файл со `status: todo`, у которого `depends` (если есть) указывает на промпт со статусом `accepted`. Если такого нет, скажи Дмитрию, чего не хватает, и остановись.
3. Если Дмитрий назвал номер или имя промпта, бери его.
4. Если есть файл со `status: rework`, он важнее новых. Его замечания лежат в `docs/design/review-log.md` в записи про этот промпт.

## 2. Сделай макет

- Полный текст задания: `docs/design/queue/_context.md` (общий контекст) и затем выбранный файл очереди.
- Если в файле указан UI kit, возьми его из `docs/design/accepted/` (там лежит принятый результат).
- Результат: **одна автономная HTML-страница** (все стили и скрипты внутри, без внешних зависимостей), обе темы на одной странице, переключатель темы в углу. Для экранов показывай несколько состояний подряд, как просит промпт.
- Макет ты делаешь только как макет: код приложения (`lib/`) не трогай.

## 3. Отдай результат

Положи файл в `docs/design/inbox/` под именем `<id>-v<N>.html`, где `<id>` из начала файла очереди (например `01-ui-kit-v1.html`), `N` — номер попытки (`v1`, потом `v2` после замечаний). Если результат из нескольких файлов (артборды), положи их в каталог `docs/design/inbox/<id>-v<N>/` с `index.html`. Рядом можно положить `<id>-v<N>.md` с короткими пояснениями: что решил сам, где отступил от промпта, что не уверен.

Как именно доставить файл, зависит от того, что тебе доступно:

- **Можешь коммитить в репозиторий.** Работай в ветке `design/inbox` (создай от `dev`, если её нет). Никогда не пушь в `main` и `dev`. Закоммить файл, обнови в файле очереди `status: delivered` и открой PR из `design/inbox` в `dev` (если его ещё нет, иначе просто допушь). Заголовок PR: `Дизайн: <id> v<N>`.
- **Можешь только читать репозиторий.** Ничего в репозитории не меняй. Экспортируй HTML, скажи Дмитрию точное имя файла из этого пункта, и он положит его в `docs/design/inbox/` сам.

В конце ответа Дмитрию напиши одну строку: имя файла и что ему с ним сделать (ничего, если ты закоммитил).

## Статусы промпта (`status:` в начале файла очереди)

| Статус | Значение | Кто меняет |
|---|---|---|
| `todo` | ещё не брали | — |
| `in_progress` | Claude Design работает | Claude Design (по желанию) |
| `delivered` | HTML лежит в inbox, ждёт ревью | Claude Design или тред |
| `rework` | есть замечания, нужна новая версия | тред ревью |
| `accepted` | принят, лежит в `docs/design/accepted/` | тред ревью |

Ревью делает тред проекта (не ты): он читает inbox, пишет замечания в `docs/design/review-log.md` и меняет статус. Свои новые версии делай по этим замечаниям.
