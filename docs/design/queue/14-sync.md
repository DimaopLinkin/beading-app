# Синхронизация между устройствами: вход, статус, ошибки

Используй UI kit из предыдущих шагов (`docs/design/accepted/01-ui-kit/` и `docs/design/accepted/01b-ui-kit-addendum/`, Liquid Glass для слоя управления, контент непрозрачный). Экран настроек (`09-settings`) уже принят: этот промпт **заменяет в нём строку «синхронизация с iCloud»**. iCloud в приложении не используется (ADR-0006: своя синхронизация через сервер, вход по почте и паролю). Слова «iCloud» и «Apple ID» на экранах не встречаются.

## Как это работает (чтобы ты рисовал правду)

- Приложение **полностью работает без входа и без сети**. Вход необязателен, это про то, чтобы схемы и прогресс были и на iPhone, и на Mac.
- Вход только **почта + пароль**. Регистрации в приложении **нет**: учётные записи создаёт Дмитрий вручную. Поэтому нет кнопок «Зарегистрироваться», «Войти через Apple/Google» и **нет «Забыли пароль»** (вместо этого мелкая подпись: «Нет аккаунта или забыли пароль? Их выдаёт и сбрасывает Дмитрий.»). Подпись нейтральная, без извинений и смайлов.
- Пароль не короче 12 символов: подсказка под полем, ошибка «Пароль короче 12 символов» до отправки. Пароль можно показать/скрыть (SF Symbols `eye` / `eye.slash`).
- Данные синхронизируются сами: при входе, при запуске, при возврате из фона, через несколько секунд после правки и при изменениях на другом устройстве. Кнопка «Синхронизировать сейчас» есть для спокойствия.
- Большие файлы (страницы книг, PDF) идут отдельно и занимают место: на сервере 1 ГБ. Есть переключатель «Синхронизировать страницы книг» и показ занятого места.
- Сервер на бесплатном тарифе иногда **засыпает** после недели простоя: тогда синхронизация не работает, пока Дмитрий не включит его. Данные на устройстве целы.
- Один аккаунт на устройство. Если на устройстве уже лежат данные другого аккаунта, синхронизация не стартует, пока пользователь не выберет, что делать.

## Экраны и состояния (каждый в светлой и тёмной теме)

### A. Строка в «Настройках»
Раздел «Синхронизация» в списке настроек (сгруппированный список iOS). Четыре вида строки:
1. не вошла: «Синхронизация», справа «Выключена», шеврон;
2. вошла, всё хорошо: «Синхронизация», справа «Обновлено только что» / «5 мин назад», шеврон;
3. идёт синхронизация: индикатор активности (системный спиннер) вместо времени;
4. проблема: справа «Нужно внимание» с иконкой `exclamationmark.triangle`, шеврон.

### B. Экран «Вход» (лист или push, как принято в UI kit; для Mac окно или лист)
- Короткое объяснение сверху в 1–2 строки: «Войди, чтобы схемы и прогресс были на всех твоих устройствах. Без входа приложение работает как раньше.»
- Поля «Почта» и «Пароль» (системные текстовые поля, подпись, правильная клавиатура/автозаполнение паролей, перевод по Return), кнопка «Войти» (крупная, внизу, в зоне большого пальца), состояние загрузки на кнопке.
- Подпись про выдачу аккаунта (см. выше), подсказка про 12 символов.
- Состояния: пусто; заполнено; идёт вход; **ошибки**: «Неверная почта или пароль», «Пароль короче 12 символов», «Нет сети: вход невозможен, приложение работает без входа» (с кнопкой «Повторить»), «Сервер недоступен» (отличать от «нет сети», см. ниже). Ошибки строкой под полем или баннером, не модальным алертом.
- Кнопка «Не сейчас» / закрыть (вход необязателен).

### C. Экран «Синхронизация» (вошла)
- Блок аккаунта: почта; кнопка «Выйти» (красная по HIG, подтверждение action sheet: «Данные останутся на этом устройстве. Синхронизация остановится.»).
- Блок статуса: большая строка состояния и «Последняя синхронизация: сегодня, 21:14»; кнопка «Синхронизировать сейчас» (во время работы неактивна, показывает ход: «Загрузка… 12 из 30»).
- Блок «Что синхронизируется»: счётчики по-человечески («Работ: 14», «Страниц книг: 120») без технических терминов (никаких «записей», «курсоров», «очередей»).
- Блок «Место»: полоса занятого места «312 МБ из 1 ГБ» (индикатор, при >90 % янтарный) и переключатель «Синхронизировать страницы книг» с пояснением «Страницы книг и PDF занимают больше всего места».
- Блок «Ожидает отправки»: если есть несинхронизированные изменения, «3 изменения ждут отправки» (когда нет сети).
- Мелкий текст внизу: «Резервная копия в файл остаётся отдельно: синхронизация её не заменяет» со ссылкой на экран резервной копии.

### D. Состояния статуса (показать каждое как отдельный кадр экрана C и как плашку)
1. **Всё синхронизировано** (спокойная галочка, `checkmark.circle`).
2. **Идёт синхронизация** (спиннер/прогресс).
3. **Нет сети (офлайн)**: «Нет сети. Изменения сохранены на устройстве и отправятся, когда появится связь.» Нейтральный тон, не ошибка, не красный.
4. **Сервер недоступен долго**: «Сервер синхронизации не отвечает. Данные на устройстве целы. Дмитрий знает, как его включить.» (так как бесплатный сервер мог уснуть). Янтарный, не красный.
5. **Нужно обновить приложение**: «Часть данных с другого устройства записана новой версией. Обнови приложение на этом устройстве.» (кнопка-ссылка «Подробнее»). Синхронизация остальных данных идёт.
6. **Сессия истекла / нужно войти снова**: «Нужно войти заново.» Кнопка «Войти».
7. **Не хватает места**: «Место на сервере почти закончилось» с действием «Отключить синхронизацию страниц книг».
8. **Ошибка с повтором**: «Не получилось синхронизировать. Повторим автоматически.» и кнопка «Повторить сейчас».

### E. Другой аккаунт на устройстве (важный и редкий лист)
Лист при входе под другим аккаунтом, чем тот, чьи данные лежат на устройстве. Заголовок «На устройстве данные другого аккаунта». Два действия, понятно описанные:
- «Привязать к этому аккаунту»: данные с устройства объединятся с аккаунтом;
- «Сделать копию и очистить»: сначала файл резервной копии, затем устройство очищается и берёт данные аккаунта.
Плюс «Отмена». Никакого молчаливого выбора по умолчанию; деструктивное действие описано явно.

### F. Первый вход (короткое состояние после успешного входа)
Не онбординг. Одна плашка/лист: «Загружаем твои работы…» с ходом, затем «Готово: работ 14». Если на сервере уже есть данные, формулировка «Объединили с тем, что было на другом устройстве».

### G. Маленький индикатор вне настроек
Компактный индикатор статуса на главном экране (библиотека «Мои работы»): в обычном состоянии его **нет** (не шумим), появляется только при «Нет сети с ожидающими изменениями», «Нужно внимание» и «Идёт долгая синхронизация» (маленькая капсульная плашка в слое управления, стекло, тап ведёт на экран C). Покажи библиотеку с плашкой в двух вариантах.

### H. Mac
Экран C и вход в окне 480–1000 pt: вход листом, статус как раздел настроек (`Settings` окно macOS, раздел «Синхронизация»), состояния D в том же виде. Показать окно в светлой и тёмной темах.

## Требования

- Нативность: лист входа, поля, переключатели, списки, action sheet, меню рисуй как системные iOS/macOS; самодельное допустимо только там, где системного компонента нет (например, плашка G), оговори это в пояснении.
- Тон: спокойный, тёплый, взрослый. **Без слащавости**: никаких «Ура!», сердечек, облачков с улыбкой и пушистых иллюстраций, ошибки без драмы и без «Упс». Иконка облака допустима как SF Symbol (`icloud` не использовать, он напоминает про Apple; предложи `arrow.triangle.2.circlepath`, `externaldrive.badge.checkmark` или другой подходящий, объясни выбор).
- Крупные цели нажатия, высокий контраст, подписи кнопок ≥ 13 pt, текст масштабируется (покажи AX3 для экрана C и листа E).
- Цвет статуса передаёт не только цветом: иконка и текст. Красный только для «Выйти» и настоящих ошибок входа, остальное нейтральное или янтарное.
- Тексты на русском, ровно такие, какими их увидит пользователь; предложи улучшенные формулировки, если мои неудачны (отметь в пояснении).
